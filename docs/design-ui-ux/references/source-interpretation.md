# Interpret the source as a design method

Use this reference when a rigid rule, fashionable treatment, or apparent conflict needs resolution. All usable knowledge has been embedded in the skill; do not request the transcript or the course's linked exercises.

## Human tutorial to agent operation

| Tutorial activity | Agent equivalent |
|---|---|
| Develop an eye through repeated exercises | Generate a representative artifact, inspect actual output, identify a specific defect, repair it, and recheck |
| Ask the client what each page should do | Infer a working task brief from available facts; ask only consequential questions that block progress |
| Move items visually until balanced | Set grouping, alignment, spacing and type roles; inspect at real scale; apply optical correction with a reason |
| Copy example interfaces for practice | Extract the underlying behavior and hierarchy; use legitimate assets and preserve the target product's identity |
| Watch a designer remove, move and regroup interface elements | Inventory capabilities, separate invariants from arrangement, compare structures and record reasons/tradeoffs; do not copy the final layout as a universal solution |
| Learn Figma shortcuts and shape tools | Use platform-appropriate containers, components, tokens, clipping, variants, and constraints |
| Prototype links between frames | Implement and exercise a state transition contract with forward, back, cancellation, and recovery |
| Review in class / show the teacher | Run task, visual, state, responsive, and accessibility checks; record observable evidence |
| Client approvals between UX and UI | Separate structural reasoning from visual work internally; do not impose checkpoints unless requested |
| Final app / portfolio exercise | Deliver the complete requested flow with realistic content, states, and handoff |
| Price a freelance assignment | Estimate real scope and dependencies if asked; do not reuse anecdotal rates or tax advice |

## Corrections and boundaries

- Treat Z-pattern scanning and inferred numbers of eye movements as explanatory heuristics, not universal laws or measured results.
- Keep familiarity, proximity, common region, and manageable choices; do not infer that familiar harmful patterns are automatically correct.
- Separate pleasing appearance from demonstrated task success. Do not use “scientific” to certify a visual judgment.
- Interpret “one primary per page” as dominant action within a task context. Allow no primary, repeated collection actions, and independent task regions.
- Do not require a primary merely to permit a secondary button. Define hierarchy by actual decisions.
- Translate the eight-pixel rule into a coherent spacing scale and clear relative grouping; retain optical exceptions.
- Treat round corners, squircles, floating pill bars, outline icons, radial gradients, and glass as stylistic options. Neither flat surfaces nor filled icons nor linear gradients are inherently wrong.
- Translate concentric corners into an inset-radius relationship plus visual inspection. Do not invent a scientific requirement that text align to a circle center.
- Treat shadow as an elevation cue. A clickable surface also needs explicit semantics and behavior; an elevated static surface can be legitimate.
- Keep nested hit areas unambiguous; tilting a decorative card is not an accessibility or event-routing solution.
- Replace “never hamburger,” “always profile,” and “breadcrumbs are bad” with navigation choices driven by tasks, hierarchy, and platform conventions.
- Treat counts of tabs as capacity heuristics. Do not assert app-store rejection or impose a fixed three-to-five rule across all contexts.
- Distinguish navigation tabs, application menus, and desktop menu bars; similar names do not imply interchangeable semantics.
- Treat a chevron as a disclosure cue, not as an accordion component itself. Follow a familiar platform's valid disclosure direction.
- Define a FAB as a floating primary action; opening a secondary menu is an optional behavior, not its definition.
- Keep comparison, review, and safeguards that serve users; fewer clicks alone does not prove a better flow.
- Use immediate short state feedback. Demonstration slow-motion animation and a forced S-curve are not production defaults.
- Use layout constraints early when useful; the claim that auto layout must always wait until the end does not transfer to robust implementation.
- Do not reproduce platform-version claims, feature availability, pricing, or release predictions without checking the current target. Preserve semantic intent instead.
- Do not encode the instructor's preference against Material Design or for Apple as a ban on either platform. Respect the target's established conventions.
- Treat a video redesign as a worked hypothesis, not proof that viewers never use categories, everyone dislikes a content format, or a proposed feature is the future. Ground priority in the supplied role, task and evidence.
- Consolidate verified redundant destinations without deleting their capabilities. Do not move every personal tool behind an avatar or replace every sidebar with top navigation.
- Translate thematic content rows into a choice between exploration and exhaustive comparison. Carousels, chips, dropdowns and grids each have discoverability/capacity tradeoffs.
- Keep search usable by keyboard, pointer and touch; “users press Enter” does not justify removing every visible submit route. Keep important captions and accessibility tools findable.
- Separate reorganizing existing functionality from inventing autoplay, shuffle, chat/rooms, recommendation algorithms or creator widgets. Include new functionality only within authorized scope and identify integration boundaries.
- Separate reference observations from its author's rationale and untested predictions. A screenshot supports appearance, a transcript supports spoken reasoning, and rendered interaction supports behavior. Do not say a video was watched when only its transcript or stills were reviewed.
- Replace the transcript's accessibility shorthand with the detailed accessibility reference. WCAG covers more than five topics; conformance is not a font-size threshold or a color-tool badge.
- Treat culturally associated color meanings as defaults plus explicit text/shape, not universal psychology.
- Do not normalize hidden cancellation, fabricated urgency, difficult opt-out, or other deceptive patterns discussed in the source.
- Keep historical brand examples as lessons about personalization, meaningful progress, presentation quality, repeated-data reduction, and utility speed. Do not repeat anecdotal company histories or causal claims as verified facts.
- Distinguish surveys, qualitative observation, experiments, behavioral analytics, and gaze tracking. Do not fabricate research from an imagined persona.
- Use mockups to provide context; an older device frame is not inherently bad if it matches the actual supported target. Always retain a legible unframed view.
